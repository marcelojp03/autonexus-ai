## CU27. Sincronizar operaciones realizadas offline

| Campo | Detalle |
| --- | --- |
| Nombre de CU | CU27. Sincronizar operaciones realizadas offline |
| Propósito | Permitir que la aplicación web y la aplicación móvil mantengan consistencia con el servidor después de registrar información sin conexión. |
| Resumen | El empleado realiza operaciones offline. Cuando regresa la conexión, la plataforma transmite las operaciones pendientes y recupera las actualizaciones correspondientes. |
| Actores | Recepcionista, Mecánico, Jefe de taller, Amazon S3. |
| Actor iniciador | Empleado autorizado, mediante sincronización manual o reanudación automática al recuperar conectividad. |
| Precondición | El dispositivo dispone de una sesión local habilitada, tiene operaciones pendientes y puede establecer conexión con la plataforma para sincronizarlas. |
| Flujo principal | **1.** El usuario realiza operaciones offline, por ejemplo registrar una inspección o avance. **2.** La aplicación guarda los datos y evidencias en IndexedDB o SQLite, junto con identificadores únicos, versiones y estados pendientes. **3.** Cuando se recupera la conexión, el sistema detecta las operaciones pendientes. **4.** Valida nuevamente la identidad y las autorizaciones del usuario. **5.** Envía las operaciones al microservicio de sincronización. **6.** El servicio verifica identificadores, versiones e idempotencia y coordina la aplicación de cambios con los microservicios propietarios. **7.** Los archivos pendientes se cargan en Amazon S3 mediante el flujo de carga autorizado. **8.** El servidor devuelve confirmaciones, errores o conflictos. **9.** La aplicación actualiza los estados locales y descarga cambios autorizados. |
| Postcondición | Las operaciones aceptadas quedan sincronizadas; las rechazadas o conflictivas permanecen identificadas para revisión, sin perder los registros locales necesarios. |
| Excepción | Conexión interrumpida; autenticación expirada; operación duplicada; versiones incompatibles; registro eliminado o modificado en el servidor; archivo rechazado por S3; almacenamiento local insuficiente; operación financiera no permitida offline. Los conflictos de negocio requieren resolución antes de confirmar los cambios. |
