## CU15. Confirmar servicio y asignar mecánico

| Campo | Detalle |
| --- | --- |
| Nombre de CU | CU15. Confirmar servicio y asignar mecánico |
| Propósito | Confirmar la ejecución de un servicio y asignar un mecánico disponible, garantizando la coordinación consistente entre las operaciones del taller, los empleados y la cotización. |
| Resumen | El jefe de taller selecciona una orden aprobada y asigna un mecánico. La plataforma coordina los microservicios de Operaciones, Empleados y Finanzas mediante una Saga. |
| Actores | Jefe de taller, Administrador. |
| Actor iniciador | Jefe de taller. |
| Precondición | Existe una orden válida con cotización aprobada y al menos un mecánico habilitado para realizar el servicio. La operación requiere conectividad para confirmar las reservas y estados distribuidos. |
| Flujo principal | **1.** El jefe de taller consulta las órdenes pendientes de asignación. **2.** Selecciona una orden con cotización aprobada. **3.** El sistema consulta los horarios y especialidades de los mecánicos. **4.** El jefe de taller selecciona un mecánico y horario. **5.** El sistema inicia la Saga y registra el proceso de confirmación. **6.** El microservicio de Empleados reserva la disponibilidad del mecánico. **7.** El microservicio de Finanzas valida y vincula la cotización aprobada. **8.** El microservicio de Operaciones confirma la asignación y actualiza la orden. **9.** El sistema comunica la asignación al mecánico. |
| Postcondición | La orden queda confirmada, con mecánico y horario asignados, y se registra la finalización satisfactoria de la Saga. |
| Excepción | Mecánico no disponible; horario ocupado; cotización inválida; fallo de alguno de los microservicios; mensajes duplicados; tiempo de espera agotado. Si un paso falla, la Saga ejecuta las compensaciones correspondientes, libera la disponibilidad reservada y evita confirmar la orden de forma incompleta. Si el resultado es incierto, permanece pendiente de conciliación, sin repetir ciegamente la operación. |
