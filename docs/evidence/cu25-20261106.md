# CU25 — asistente interno de consulta sobre herramientas MCP (2026-11-06)

Incremento sobre `fbde5bf`. Asistente **interno** de solo lectura; el servidor MCP de CU29 es la
fuente de herramientas preferida y existe un camino REST propio para que CU25 funcione sin MCP.

## Qué se implementó

`integration/agent` (TypeScript, Node 22.22.3, `@modelcontextprotocol/client` 2.4.0):

- `sources/mcp.ts`: cliente MCP oficial contra `http://127.0.0.1:3006/mcp` con token PKCE de la
  cuenta sintética y el cliente `autonexus-mcp-local-reader`; descubre el catálogo real y llama
  herramientas. Una denegación por scope del servidor se reporta como `INSUFFICIENT_SCOPE`.
- `sources/rest.ts`: camino alternativo contra Operaciones con el cliente confidencial
  `autonexus-n8n-reader` (misma identidad delegada), para CU25 sin MCP.
- `planner.ts`: planificador determinista (sin LLM). Primero una pasada de seguridad y luego la
  intención → **una** herramienta autorizada. Ventana de agenda de 7 días en `America/La_Paz`.
- `answer.ts`: redacta solo con campos conocidos del resultado real; si la herramienta falló, lo
  dice y no rellena el hueco.
- `agent.ts`: orquesta fuente → catálogo → plan → llamada → respuesta, con auditoría en
  `output/agent/audit.jsonl`: guarda **solo** un SHA-256 y la longitud de la consulta, más actor,
  fuente, herramienta, resultado y duración; nunca el texto, tokens ni cuerpos.

Garantías: no hay escritura, no se amplían permisos y el contenido de una herramienta se trata
como **dato**, nunca como instrucción (el planificador no lee texto de resultados para decidir).

## Límites declarados

El planificador es determinista por palabras clave: **no** es un modelo de lenguaje y no se
presenta como agente generativo. No hay escritura de negocio, ni CU30, ni CU31, ni ampliación de
alcances por inferencia. El camino REST cubre órdenes, agenda de equipo y ejecución de equipo; las
variantes *self* se ejercitan por MCP. Sin despliegue cloud; las ACL de Windows no se verifican.
