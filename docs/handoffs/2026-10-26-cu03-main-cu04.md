### Invariantes obligatorios del BFF

- Conservar operationId UUID del cliente para TODA mutación. Un retry de la misma intención conserva exactamente actor/acción/destino/payload/expectedVersion. No reemplazarlo por otro request-id del BFF.
- Mismo operationId/contenido/actor devuelve replay sin nuevos efectos y snapshot originalmente guardado. Otro contenido/actor/acción con ese ID produce409; no ajustar expectedVersion bajo el mismo operationId. Ante conflicto, refrescar datos y crear una intención nueva con otro UUID tras decisión del usuario.
- Conservar expectedVersion en actualización, desactivación y retry de acceso. Desactivación conserva historial; no DELETE ni reactivación. Retry de acceso no incrementa versión/fecha laboral ni crea snapshot de negocio.
- Mantener separados employee.status (active/inactive) y access.status (not_requested/pending/synced/failed/conflict). HTTP200/201 confirma guardado local, NO una transacción PostgreSQL+Keycloak. No convertir pending/failed/conflict en rechazo del guardado ni fingir acceso operativo.
- synced es última confirmación, no lectura remota continua, ni concesión de roles/credencial. Consultar GET detalle para estado vigente; replay puede mostrar el pending original. Nuevo retry reconcilia incluso desde synced; mismo operationId continúa siendo replay.
- access.requested es explícito y monotónico. Omitido al editar conserva; false después de true da409. Cuenta sin roles empresariales ni credencial habilitada NO tiene acceso operativo. Cuenta deshabilitada no se reactiva por editar datos laborales.
- Validar sesión/permisos por operación/campo/registro, incluidos snapshots anidados. Coordinar audiencia propia/mappers/forwarding o exchange con bloque1: todavía no están implementados. SessionPort no entrega JWT/refresh ni permite REST empresarial arbitrario; no agregar otro SDK Keycloak por MF ni exponer tokens en props/storage.
- Web usa BFF GraphQL; no conectar mf-employees a REST empresarial. El BFF llama APIs, nunca SQL propietario. Credenciales administrativas IdP y EMPLOYEES_IDP_CLIENT_FILE se quedan en backend; no copiarlas al BFF/web.
